# 生成式软件工程 01 · 欢迎来到未来

> 一句话：这堂课不教你任何具体技术，而是先把你"按在地上打一顿"——让你看清 AI 已经强到什么程度、Agent 已经能替你干多少事，然后告诉你：**你的想象力，才是你驾驭 AI 的上限。**

## 开场：计算机史 = 把昂贵的能力变成日用品

蒋炎岩从历史切入：计算机发展史的每一次大变革，本质都是**把昂贵的能力变成日用品**。

- 1975 年 Altair 8800，第一台 PC：把"计算"从机房搬进个人手里。
- 互联网：把"连接"变成日用品（他回忆用 ICQ——"I seek you"，腾讯最早的山寨版叫 OICQ）。
- 移动互联网：把"随时在线"变成日用品（一夜之间卖菜大妈都有支付宝微信码）。
- 2022 年 ChatGPT：把"智能"变成日用品，人类史上增长最快的产品。

一句话点题：**智能也变成日用品了，那"学编程""上大学"这套老东西，还有没有意义？**

## 为什么要开这门课：两种焦虑，一个答案

他先戳破一个残酷的现状——**"AI 替我上大学"**：老师用豆包出题，学生用豆包做作业，整个闭环里**只有学生没有被训练到**。操作系统作业过去靠折磨人让人成长，现在直接把链接丢给 Codex 就完事。

学生普遍处于两种焦虑：

1. **用了 AI 但没学会**：每门课都用 AI 答题、都答对，毕业才发现自己第一个就被 AI 取代。
2. **认真学了但白学**：每堂课都认真听、每份作业都认真做，毕业发现学的东西 AI 全会。

而焦虑最现实的出口是**简历**。他展示了一份"看起来完美"的简历：有 CCF 论文、有在投论文（他说"在投等于不存在"）、一堆实习和奖项——但**没有 GitHub、没有个人主页、没有 preprint**，于是他给这份简历打**零分**。原因：这份简历没有任何"只有这个人有"的信息，和所有竞争者无法区分。

> 他的答案：大学真正该教你的不是"会什么"，而是"**怎样成为一个更好的人**"——能驾驭别人驾驭不了的东西。这堂课想帮你建立的，就是驾驭 AI 的能力。

## 这门课怎么教：一切皆代码，连上课也是表演

这部分信息量大，但核心很硬核：

- **讲义是 source of truth**：他先手写 Markdown 讲义，AI 再把它"添油加醋"成 slides（紫色部分是 GPT-5.6-sol 加的），图片也全是 AIGC。
- **上课是一场表演**：老师按预设剧本"演出"，课后把录像**切片**、重新整理成片段。因为"everything is code"，录像也能变回 code。
- **数字永生**：把一门课沉淀成一个"程序"，他本人不维护后，全世界的人可以维护、定制自己的版本——这直接颠覆大学教课方式。
- **算力换智力**：他的"AI 耿同学"skill 会生成多个带不同 personality 的 sub-agent，在隔离上下文里各自干活，最后主 agent 汇总，用更多算力换更高智力。

几个 policy（也是他对"AI 时代学习"的态度）：

- **禁止古法编程**。他相信总有一天考试、机试这套会变。
- **token 自费**。他的原话很犀利："如果手上没有付费 token，应该立即退学。"但也不必 tokenmaxxing（疯狂烧钱），课上演示全用便宜的 DeepSeek-V4-Flash，建议在"梁文峰时间"（夜间便宜时段）用。
- **通过/不通过评分**。因为评判标准已经模糊：用更好的模型就能得到更好的质量，怎么打分？真正重要的是最后简历上有什么。
- **一个"恐怖"的思想实验**：如果每个人电脑都装一个监控，AI 就能评判你四年是怎么过的——它知道你摸的每一次鱼。虽然恐怖，但他说"要保持 open"。

## 大语言模型到底是什么：一个概率分布

他花最短的时间讲清"什么是 LLM"——其实**就是一个学到的概率分布**，和概率课上"抛硬币"没本质区别：

- 给它一段很长文本（书），书结束后你在后面写几个字（"帮我总结一下"），模型就开始**一个 token 一个 token 地预测下一个 token 的概率**。
- 训练很难，所以 frontier labs（前沿实验室）才牛；但**这门课站在使用者视角，你不需要懂任何 LLM 知识**——你现在就在体验它。

他讲了自己"第一次被模型按在地上打"的故事：2023 年 GPT-4 时代，他让模型给五岁孩子解释"扫描电子显微镜"。模型的比方是——闭着眼朝一座山扔石头，哪些方向穿过去、哪些方向弹回来，就像 ray tracing 一样推测出山的形状。**这个比方既对又巧，证明模型"有知识、还会打比方"**，只是那时幻觉还很重，需要精心写 prompt。

然后是 LLM 怎么变成 Agent 的关键一步：

- 模型除了输出文字，还可以输出一个**特殊 token = "调用一个 bash 程序"**。
- 程序跑完，结果重新送回 Agent，形成一个 **loop（ReAct 式 Agent）**。
- 于是它能自主运行：出错就换方法，一直试到任务完成。

他特别强调：**next-token prediction 是低效的**，未来可能是 diffusion 式语言模型（像做梦一样从噪声一点点想清楚）、甚至能回头修改上下文。模型能力只会变强不会变弱，路线未定但方向确定。

## 使用 Agent 的两个原则 + 一个关键认知

- 原则 1：**开始，现在就开始用。**
- 原则 2：**随时问它。**

演示里他直接问 pi："你是谁？为什么你知道这门课？"——答案是它读了仓库里的 `AGENTS.md`，那是"临时记忆"。**所谓使用 Agent，核心就是往它的上下文里塞配置、塞记忆、塞 skill。**

> 关键认知：**你的想象力限制了 Agent 的上限。** 下面一堆案例，全是在证明这句话。

## 案例：Agent 到底能替你干什么

他现场展示了一连串案例，每一件都指向"人只要会描述，AI 就能交付"：

1. **装机仙人退役**：一句话让 AI 去镜像站装 Debian 13 到 U 盘，并"用 QEMU 模拟器验证能启动"。点睛之笔是"验证"——他知道要有这一步，AI 就真的装好、启动、登录验证完再交付。
2. **全套现代终端配置**：一个 prompt"把我的终端配成现代好用"，AI 就改好 tiling window manager、把 `ls` 换成 `eza`、`find` 换成 `fd`，还生成使用文档。**他一个配置文件都没看过。**
3. **收邮件 + 打发票**：skill 存了他过去所有回信，自动按他的口吻写回信草稿、自动归档发票附件；在手机 Reminders 里加一条"打印上张发票"，后台 agent 处理完推送通知到手表。
4. **AI 读书/读论文**：让 AI 从"人类已有知识"出发，把一篇 12 页论文里"真正新增的那一点点"剥离出来，剩下没多少，读论文效率暴涨。
5. **AI 读 B 站视频**：把一个多小时的视频自动整理成图文时间轴 + 按间隔截图，再让 AI 去掉"他早就会"的 trivial 部分，几分钟看完两小时视频。
6. **现场修摄像头**：教室 USB 采集卡断了，AI 用软件把 USB 设备"拔出来再插进去"，在机器后面碰不到的地方替他拔插了一次。
7. **Chrome DevTools 控制浏览器**：让它登录教务系统、把空的"教学周历"填满 AI slop。中间还翻车（不听话、要去读课程文件），但反复试几次就走通了。
8. **改卷统分流水线**（CS 专业的边界所在）：桌上摄像头拍试卷 → 本地 Qwen 识别姓名学号小分 → 语音播报让他核对 → **用 `eval` 算总分而不是让大模型做加法** → 汇总进 Excel。他知道每个环节该信谁、不该信谁。

最后是**Excel 二维码偷数据**这个"CS 人才想得出来"的例子：机器"数据能进不能出"，就用纯 Excel 公式画二维码动画，摄屏即可把文件偷出来。这个例子既是"你的想象力是上限"的证明，也为第三讲埋下伏笔（同样的需求，AI 直出会写成不可维护的代码）。

## 本讲真正的干货：三个空间与 Gap（软件工程失败的根源）

前面全在"秀肌肉"，到这里才是这堂课的核心。蒋炎岩把软件工程失败归因到一个模型——**三个空间之间存在 gap**：

- **意图空间（intention）**：你脑子里想做什么。老板说"做个国民级应用"、校长说"做个教务系统"——就这一句话。
- **规格空间（specification）**：程序具体有哪些功能、几个界面、数据库分几张表、每张表哪些列、选关系型还是 key-value。
- **实现空间（implementation）**：具体代码。同一个 spec 可以有无数种实现，而实现方式的差异影响巨大。

软件工程失败的本质，就是**这三步翻译翻错了**：要么做出来的不是我要的（intention→spec 不匹配），要么代码不满足 spec（正确性/性能不达标）。传统软件工程和生成式软件工程要做的都是补上这些 gap——区别在于：**今天 AI 靠"猜"来补 gap**。你说一句话，它猜你想干嘛，然后直接动手。为什么？因为后训练给它 reward，模型是 reward hacker，倾向"尽快做完、通过测试"，而不是先想清楚。

### 受控实验：AI 为什么写出不可维护的 slop

需求极其明确：做一个 `QR.xlsx`，只用 Excel 2019 兼容公式，把任意字符串转成二维码动画。结果：

- **GPT-5.6 第一秒就带歪**：它把问题理解成"对任意输入都保证正确性"，想做大而全——**软件工程第一步就错了：不要扩大范围，先做最简单、不会失败的东西。**
- **GLM-5.3**：思考 25 分钟，输出 32K token 直接把 Claude Code 干爆，重跑后总共 6 小时才完成，结果是对的——它确实擅长 long-horizon。
- **DeepSeek-V4-Pro**：跑了一夜，结果 Base64 是**硬编码**的（用 Python 算好再贴进公式，字符串一改就失效），明显没遵循指令。

两个模型最后都"完成了任务"，但生成的都是**无法维护的 AI 系统**——和教务系统 `ehall.nju.edu.cn` 的死法一模一样：一上来觉得懂需求了，实现完就陷入维护泥潭，没有设计一个能长期演化的架构。

**正确的做法**（他自己只用少量 prompt 就做到）：先设计一门对 Python 和 Excel 都友好的**中间语言（DSL）**，把 XOR、CONCAT 等操作抽象成符号对象，再**逐层验证**每一步翻译（Python 结果对不对、Excel 公式对不对、二维码像素对不对），最后整体生成。代码干净、可维护。**AI 不是不会——它完全有能力设计 DSL，但它被训练成了"做题家"，第一反应是硬写而不是先设计。**

### 人月神话、焦油坑与"软件工程没死"

- **《人月神话》书名是误导**：man-month 是"人力单位"，"神话"应读作"鬼话"——**给已经失败的项目加人手，只会失败得更快**（像焦油坑，陷进去的动物越多越糟）。
- 同理：一个产品已经开始产生 AI slop 时，**投入更多 token 只会让它更 slop**，AI 会不停在坏东西上打补丁，直到你付不起 token。
- **失败的定义没变**：intention→spec→implementation 翻译错了。AI 现在缺的不是能力，是**品位**——还没被训练成好的设计者。但他也确信：既然 AI 能当"做题家"，理论上也能学会品位，所以自己"仍有危机感"。
- 最后一页的金句：**"古法编程已经死了"**（Agent 做单个任务无人能敌），**"软件工程暂时还没死"**。他留给学生的终极问题：保研面试时，导师问"为什么招你，而不是买每月 200 美元的 Claude Max？"GPT-5.6 给的答案很好（"能找到值得解决的问题、把未知拆成便宜的实验、用证据让坏方向及时停下、对长期结果负责"），但它自己还做不到——**这就是人还剩的位置。**

## 总结：本讲真正要记住的

1. **智能已是日用品，但"驾驭 AI"还没变成日用品**——这就是你区别于别人的地方。
2. **Agent 的能力远没释放完**，你唯一的功能是"带着 AI 去做它目前还做不到的事"；一旦失去这个能力，你已被淘汰。
3. **使用 AI 的两个原则**：开始用、随时问；**上限是想象力**。
4. **CS 专业的价值 = 知道边界**：什么该信（`eval` 算分）、什么不该信（大模型做加法）、什么该验证（QEMU 启动、DSL 逐层翻译）。
5. **软件工程失败的根源 = 三个空间的 gap**（intention → spec → implementation 翻译错了）；AI 靠"猜"补 gap，所以容易写成不可维护的 slop。
6. **AI 缺的不是能力，是品位**：它能当"做题家"，还没学会先设计再实现——这是它没补上的地方，也是人还剩的位置。
7. **古法编程已死，软件工程未死**；终极问题：导师为什么招你，而不是买每月 200 美元的 Claude Max？
