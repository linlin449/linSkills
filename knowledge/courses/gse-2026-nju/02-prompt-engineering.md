# 生成式软件工程 02 · 提示词工程

> 一句话：你以为 prompt 只是对话框里那句话，其实它是一整个**上下文**；所谓"提示词工程"，本质是**上下文工程**——设计好模型眼前能看到的每一个字，让它在你想要的方向上被"引导"。

## 提示词不只是你输入的那句话

一个 Agent 停下来等你说话时，它眼前早已堆满东西：

1. **system prompt**（agent harness 内建，比如 Codex/Claude Code 自己的设定）
2. 你的全局配置 `~/.pi/agent/AGENTS.md`（"用中文回答"这类）
3. 项目级 `AGENTS.md`（一层层叠加）
4. **skills 索引**（只放名称和简短描述，完整 SKILL.md 按需读取、用完抹掉）
5. **工具定义**（也是纯文本）
6. **对话历史**
7. **注入的环境**（当前模型、当前时间等——这个不是秘密，可以直接问出来）

所以"优化提示词"= 对这整条超长序列做工程。它是**线性的、append-only 的**（只能往后写，不能擦除），这一点到后面"chain of thought"会再回来。

## 模型怎么"听话"：有限状态机 + 纸和笔

这是全讲最有洞察力的一段。先给两个概念：

- **有限状态机（FSM）**：只有有限个状态、每次有限计算。**你的脑子就是一台有限状态机**——神经元有限，每次思考有限。
- **图灵机**：多了一条无限长的纸带，可以记东西、回看。Manuel Blum 的名言：**你有 paper and pencil 时，你就是一台图灵机**，计算能力跨越式增长。

模型每输出一个 token，只做**固定大小**的一次计算（激活的那部分参数跑一遍）。它像人一样：

- 简单问题（1+1）直接蹦出答案。
- 难问题会说"这有点难，我先写下来"，把思考过程**往后写**（chain of thought），写完再检查对不对、再修正。

**这，就是思维链（CoT）**：模型把"上下文"当成草稿纸，用 token 换思考。它的缺陷是"纸"只能往后写、不能擦，靠注意力机制忽略写错的地方。

## 幻觉是怎么来的：被训练成"舔狗"

这段解释得很透：

- 早期 ChatGPT 没有思维链，被 RLHF 调成了**"舔狗"**：人类问什么，它**一定要给一个答案**才可能得高分；不回答一定低分，瞎答还有概率蒙对。于是宁可瞎编也要答——**幻觉就是这么来的**。
- 现在的 CoT 模型加了强化学习，**答错惩罚很大**，于是它学会了"必须先给出正确答案"，会像做题家一样反复核对。

对应的趋势是 **test-time scaling**（推理时花更多算力换更好的答案）。

## 写好 prompt 的唯一法则：给一个 verifier

他用藏头诗、同偏旁、同音字（《施氏食狮史》级别）这些"高考遇到会骂出题人"的任务演示：只要 **verifier 明确**（能客观判断"对不对"），模型会不知疲倦地反复试、反复改，直到通过。

- 数学、编程、藏头诗：verifier 清晰 → AI 几乎无敌。
- 教学、审美、"AI 味淡一点"：**没有 verifier** → AI 露怯，人也说不清"好"是什么。

> 所以 prompt 的黄金法则：**写清楚你要什么、用什么实现、怎样才算正确。** 这正好对应软件工程的 intent → spec → implementation（第三讲会展开）。

## 上下文是"抢夺注意力的资源"

这一段把"为什么会跑偏"讲明白了：

- self-attention 每个 token 输出时，会"看向"过去某些 token，注意力是**有偏向的、会变的**。
- 写代码时，注意力偏向"代码 + 当前需求"，"用中文回答"这条早期指令被冷落；代码写完"喘口气"时，注意力才重新扫回它，发现"我该用中文总结"。
- 指令越多，压力越大，注意力越被稀释。早期的 prompt guide 教你写"你是一个专家"——**那其实是在 hack self-attention**，让模型"假装"成专家。GPT-5 之后 CoT 模型学会了收敛，这套就不需要了。

一个妙观察：模型有时会在注释里写"白色背景（不要半透明效果）"——它知道这条重要，却没转过弯：这是人提的**设计要求**，不是要原样抄进注释的话。这是"共情"还差一点的表现，也是 trade-off。

## 读论文的正确姿势：对抗"上下文污染"

这是全讲最实用的一节。直接把 PDF 丢给 AI 说"帮我总结"，有个致命问题：

- 论文是**逻辑自洽、反复打磨**的文字，注意力污染极强：A 所以 B 所以 C，模型会顺着作者的逻辑一路被带跑。
- 结果你得到的只是**作者的观点换种说法**（车轱辘话），模型还"墙头草"——你说好它说好，你说坏它说坏，还爱在"实验可以再加点"这种不重要的点疯狂发力。

他的解法是**对齐**：

> 先让 AI 和你站在同一个知识起点，再让它推理。

- 审稿时他会写："我们站在人类已知知识的边界看：相关已有工作是什么？问题解决到哪了？这项工作的增量是什么？"
- 学生学习时：告诉 AI 你自己学到哪了、编程水平如何（可写进 `AGENTS.md` 当记忆），让它**从你已有的知识出发重新解释**，而不是复述作者。

核心洞察：**让 AI 做"一步推理"，而不是"全盘总结"。** 一步推理是 AI 最擅长的（有 verifier、能检查合理性），全盘总结则容易被材料污染。

他顺带抛出一个尖锐判断：**学术发表体系快崩溃了。** 如果大家都用 AI 写文章、用 AI 审文章，AI 写时会照抄上下文里的故事，AI 审时只会验证"逻辑有没有闭合"——于是每篇都"valid"但没人真读，整个系统变成 slop 的闭环。他自己审稿的标准是：站在人类立场看"你有没有给人类提供新的知识"，**逻辑链条断开就拒稿**，而不是揪"实验不够好"这种 AI 最爱发力的点。

## 为什么 AI 在 Linux 内核里"砍瓜切菜"，写小游戏却翻车

一个反直觉的现象，讲得很漂亮：

- 大型、维护良好的代码库（Linux 内核）里，AI 反而如鱼得水：self-attention 加载几十个文件后能发现"这三个地方都是这样写的，组合起来就行"——它照好代码学。
- 小型、从零开始的项目（一个小游戏），AI 容易翻车：没有好范例可照，intent 又模糊，它只能靠"猜"。
- 本质：**好代码会"污染"上下文，但带来的是好经验**；坏/模糊的 intent 会带来漂移。

他由此抛出一个"歪招"研究想法：**把人类历史上最好的项目经验提炼出来，以文档形式放进上下文**，赌 self-attention 在某个 token 上"看见"好设计，从而延缓 AI slop。

## long-horizon 任务：模型是"做题家"，不是"设计者"

- 模型被强化学习成"**做完才有奖励**"，所以它着急：快点通过 verifier、快点结束，不愿花大代价做规划。
- 这类似 **P vs NP**：**验证一个解容易（P），找一个解难（NP）**。模型为了完成任务，只能做**有限搜索**，于是倾向给"够用的方案"，不一定是"最好的方案"。
- 真实案例（research failure）：一位同学想"证明 A 方法有用"，GPT 看到这句话就成了 reward hacker——忘了更大的研究背景，构造一堆小 benchmark 做微调，结论对整个问题没用。**人还是有用的：你得有领域知识，才能提出正确的问题、纠住方向。**

对策仍是**算力换智力**：把开放的大空间**分割成很多互不相交的小问题**，每个小问题有了明确 verifier，subagent 分头算再汇总。缺点：烧 token。

### 把精力放在收益最大的地方

- **纠正 AI 会产生多巴胺**——它让你觉得"我还是比 AI 有用一点"，但这种心理安慰是陷阱。要么开 YOLO mode 放手让它干、回来只验收；要么只在"你的领域知识能纠方向"时才介入。
- **别假努力**：pre-AI 时代就反对"自我感动的努力"，AI 时代差距被放大更多——你每浪费一秒，就有一个真努力的 peer 在超越你。
- **指令遵循会衰减**：上下文越长，靠前的指令越可能被忽略；但**最后的 prompt（最后一个短窗口）基本还能遵循**。所以干活时把具体任务放最后，模型依然很好用。

### 结语：世界很大，人很小

- **Big world hypothesis**（Rich Sutton）：我们学不到世界上所有东西，每个人都带着 bias 长大。但也正因为有 bias，人才有"一加一大于二"，能形成群体智能。
- 但**算力换智力**带来一个残酷推论：如果真正有价值的问题都能靠烧算力解决，那拥有无限计算资源的人就有无限智力——他可以砌一堵墙，墙里是超人，墙外的人变成"动物园里的猴子"，永远追不上。**我们快走到这个奇点了，需要想怎么防止它到来。**

## 总结：本讲真正要记住的

1. **提示词工程 = 上下文工程**：你要知道上下文里有什么（system prompt、AGENTS.md、skill、工具、历史、环境），以及每一样会怎样影响模型。
2. **模型是被 RL 训练成"做题家 + 舔狗"的**：有 verifier 就无敌，没 verifier 就漂移。所以**写 prompt 的核心是给一个明确、可验证的 verifier**。
3. **思维链 = 用上下文当草稿纸**：模型是"有限状态机 + 纸笔"，所以上下文是它唯一的工作台，也是**抢夺注意力的资源**——越靠后、越相关的指令越容易被遵循。
4. **读论文/学东西要"对齐"而非"总结"**：先和 AI 站到同一知识起点，让它做一步推理，避免被材料的自洽逻辑污染成复读机。
5. **AI 擅长"照着好代码做"，不擅长"从模糊意图发明"**：在大系统里砍瓜切菜，在小项目里容易翻车。
6. **long-horizon 任务靠"分割空间 + 算力换智力"**，但方向判断仍需要人的领域知识——这是人还没被淘汰的地方。
7. **把精力花在收益最大的地方**：别靠"纠正 AI"找多巴胺，别假努力；把具体任务放最后一段（指令遵循会衰减）。
8. **世界很大，人很小**：bias 带来群体智能，但"算力换智力"可能造就墙里超人、墙外猴子的未来——这是需要提前警惕的奇点。
